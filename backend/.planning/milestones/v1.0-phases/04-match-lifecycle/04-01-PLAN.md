# Phase 04 - Plan 01: Match Lifecycle States & Operations

## Overview
Implement the Match Lifecycle endpoints that transition a Match from `MATCHED` to `ARRIVED`, `IN_PROGRESS`, and `COMPLETED`. This involves adding geographic boundary validation (GPS) to grounds (`carts`) and enabling players to verify their presence and declare the match finished.

## 1. DB Schema Enhancements (Locations & Carts)
The `Cart` model represents the specific ground where play occurs. To enforce GPS arrival bounds, we need to store the exact ground coordinates.
- **Model Update:** Edit `modules/cart/model/cart_model.py`. Add:
  - `latitude = Column(Float, nullable=True)`
  - `longitude = Column(Float, nullable=True)`
- **Schema Update:** Update `Cart.to_dict()` logic to include the new fields.
- **Migration Script:** Create `core/database/add_coordinates_to_carts.py` using `sqlalchemy` raw `text()` execution (idempotent `ALTER TABLE` to add columns `latitude` and `longitude` of type `FLOAT`).

## 2. MatchService Updates (`modules/match/service/match_service.py`)
Implement the core lifecycle transitions containing business logic and locks.

### A. `arrive_match(user_id: int, match_id: int, user_lat: float, user_lng: float) -> dict`
- **Validation:**
  - Retrieve the match using locking (`find_by_id_orm` with `with_for_update`).
  - Match status must be `MATCHED` or `ARRIVED`.
  - Ensure the user is in the match (`has_player`).
  - Verify the `Cart` assigned to the match has `latitude` and `longitude` set. If set, calculate proximity using Euclidean distance or basic bounds (e.g., `abs(user_lat - cart_lat) < 0.005` & `abs(user_lng - cart_lng) < 0.005` roughly 500m). If the cart lacks coordinates, bypass the check gracefully for v1.
- **State Changes:**
  - Update `MatchPlayer.has_arrived = True`.
  - Evaluate total arrivals: If all `joined_players` have `has_arrived == True`, set Match status to `IN_PROGRESS`. If only some arrived, set to `ARRIVED`. 
- **Return:** Updated Match dictionary.

### B. `finish_match(user_id: int, match_id: int) -> dict`
- **Validation:** 
  - Retrieve match with locking. Ensure the user is a player in the match.
  - Status must not be `COMPLETED` or `CANCELLED`.
- **State Changes:**
  - Set Match status to `COMPLETED`.
  - Update the assigned `Cart` status back to `AVAILABLE` to free the ground in advance of the strictly scheduled timeslot end.
- **Return:** Updated Match dictionary.

## 3. Match Routes (`modules/match/controller/match_routes.py`)
Expose the new behaviors as protected endpoints.
- **Arrival Schema:** Create `MatchArriveSchema` (or parse directly via pydantic/request body) to validate incoming `latitude` and `longitude` floats.
- **`POST /api/v1/matches/{match_id}/arrive`**:
  - Requires `user_id` from token.
  - Calls `match_service.arrive_match` and returns success structure.
- **`POST /api/v1/matches/{match_id}/finish`**:
  - Requires `user_id` from token.
  - Calls `match_service.finish_match` and yields success response.
